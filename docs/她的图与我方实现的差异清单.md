## 二、我方相对她的偏离：5 处

### 2.1 `fastp -> bwa` 保留为 data 边（她标的是 order）

她自己的数据证明这是数据边：

| | 语义格式 |
|---|---|
| fastp 输出 | `RAW_PAIRED_END_R1_FASTQ`、`RAW_PAIRED_END_R2_FASTQ`、`QC_STATS_REPORT` |
| bwa 输入 | `RAW_PAIRED_END_R1_FASTQ`、`RAW_PAIRED_END_R2_FASTQ`、`REFERENCE_GENOME_FASTA` |
| 交集 | **R1 + R2，非空** |

而且她把同样吃 R1/R2 的 `fastp -> star` 标成了 `data`。改成 order 会切断 WES 链路的
数据流。**判定为她的标注不一致，保留我方的 data。**

### 2.2 multiqc 排除出原子层

她的图里 multiqc（T013）有 12 条入边。但 multiqc 是终端 QC 汇总器，没有下游消费它的
输出，放进原子链只会产生过不了闭集校验的 fan-in。按要求彻底移出：运行时目录 50 个工具
而不是 51，提示词里删掉教模型写 MultiQC 步骤的段落。

### 2.3 样本级 `specimen_types` 走旁路，不写进图

0811 的 `sample` 表改成 run 级后不再携带 `specimen_types`，而
`pipeline_router.STUDY_ROLE_RULES` 判定 tumor/normal 完全依赖它。8,353 行从改造前的
备份提取到 `data/0811_supplement/sample_specimen_backfill.csv`，在 matcher 启动时加载成
内存映射。**图里一个属性都不写**，图上已有的值永远优先。

六个配对判据 study 覆盖率：HRA000021、HRA000873、HRA001272、HRA001748、HRA001749
均 100%，HRA006499 为 482/523。

### 2.4 `read_pair` 从语义格式推导（纯代码，不碰图）

0811 的 T1 没有 `read_pair` 列。原文件名启发式要求下划线分隔，漏掉
`10125714.R1.fastq.gz` 这类点分隔命名，26,053 个 FASTQ 里判不出 1,116 个。
改为优先用她的 `semantic_format`，覆盖率 100%，修复后缺失数为 **0**。

### 2.5 `strategy` 归一到路由词表（纯代码，不碰图）

按她自己的 `reference/strategy_modal_map.csv` 折叠：WXS→WES、Targeted-Capture→WES、
TCR-Seq→bulk_RNA。484 行 `Unknow` 她自己标了 `action=skip`，保留原值不猜测。

### 另外：NEXT 拓扑是按她的对齐的

我方原有 `fastqc->fastp`、`fastqc->bwa` 两条边她没有，**已按她的删除**。
现在 12 对非 multiqc 边与她逐条相同。

## 六、执行端命名标准：对齐 workflow.zip 的知识卡

`workflow.zip`（sha256 `511df387…`）带 25 张 `knowledge_card.yaml`，`interface.params`
的 `name` + `target` 就是执行端参数的权威命名。我方 `config/knowledge_card_execution_contracts.json`
原先来自更早的 `wes_somatic_pair+rnaseq_singletask.zip`（sha `7d870e3a…`），只覆盖 12 个
原子工具，本次已按新卡逐条核对补齐。

### 6.1 命名规范（从 25 张卡归纳）

| 层级 | 约定 |
|---|---|
| 卡 id | 动作化 snake_case：`star_rrna_and_genome_alignment`、`samtools_alignment_processing`、`featurecounts_gene_counting`、`bwa_mem_paired`。短名放 `compatibility.legacy_aliases`（`star`/`samtools`/`bwa`） |
| WDL 工作流名 | PascalCase：`StarRnaSeqWorkflow`、`SamtoolsAlignmentWorkflow`；少数流程级卡直接用 snake_case（`driver_gene_gender_analysis`） |
| 参数 target | 一律 `<workflow_name>.<param_name>` |
| 输入参数名 | 语义化 snake_case：`read1`/`read2`、`alignment`、`input_vcf`、`maf_file`、`clinical_file`、`metainfo_file`、`counts_tsv`、`expression_matrix` |
| 样本标识 | 单样本用 `sample_id`，tumor/normal 配对用 `pair_id` |
| 输出名 | 语义化 snake_case + `artifact_type` 标注：`sorted_bam`[bam]、`sorted_bai`[bam_index]、`pass_vcf`[vcf]、`km_plot_png`[plot_png] |
| 暴露层级 | `basic`（业务必填）/ `advanced`（可调，如 `threads`）/ `infra`（`docker_image`、`memory`） |

### 6.2 本次补齐的内容（纯增量，16 项输入 + 5 项输出）

| 工具 | 补的输入 | 补的输出 |
|---|---|---|
| `bcftools` | `pair_id` | `pass_vcf_index`、`normalized_vcf_index` |
| `samtools` | `threads` | **`dedup_bai`** |
| `star` | `sample_id`、`threads` | `rrna_star_log`、`genome_star_log` |
| `trim_galore` / `featurecounts` / `rsem` | `sample_id`、`threads` | — |
| `bwa` | `read_group_platform`、`threads` | — |
| `snpeff` | `pair_id`、`snpeff_memory`、`snpeff_config` | — |
| `fastqc` | `threads` | — |

补的输入全是标识与调参（string/int），`managed_by: executor`，合同校验只对
`required && managed_by=="mcp"` 报错，所以这次补齐不会引入新的校验失败。
`docker_image`/`memory` 这类 `expose_level: infra` 的运行参数按设计不纳入合同。

其中 **`samtools.dedup_bai` 值得单独说**：GATK 配对模式需要 tumor/normal 两侧的 BAI，
而我方合同原先只声明了 `sorted_bai` 和 `dedup_bam`，漏了 `dedup_bai`。一旦
`remove_duplicates=true`，去重后的 BAI 就传不下去。

### 6.3 两处结构性差异

**1. `fastp` 和 `gatk` 在 workflow.zip 里没有卡。** 我方合同引用的
`fastp_paired_end`、`gatk_wes_somatic` 来自更早的归档。新包里 `atomic_tools/` 只有
bcftools、bwa、snpeff，`rnaseq_tools/` 只有 fastqc、featurecounts、multiqc、rsem、
samtools、star、trim_galore。**需要确认这两张卡是否会单独补发。**

**2. 配对 WES 的建模粒度不同。** 新包把它作为**一张整卡** `wes_somatic_pair`
（`WesSomaticPair`）交付：

```
输入  tumor_r1 / tumor_r2 / normal_r1 / normal_r2 / interval_list
输出  tumor_bam / tumor_bai / normal_bam / normal_bai
      unfiltered_vcf / filtered_vcf / pass_vcf / normalized_vcf / annotated_vcf（各带 index）
      snpeff_html / snpeff_csv / multiqc_html
```

而我方是拆成 `fastp ×2 → bwa ×2 → samtools ×2 → gatk` 的原子链，`tumor_bam`/`tumor_bai`
在我方是 GATK 的**输入槽**，在卡里却是整卡的**输出**。两种建模都成立，但执行端只认整卡。
**需要确认：配对 WES 走整卡提交，还是继续走原子链？** 这直接决定 GATK 四槽要不要保留。
