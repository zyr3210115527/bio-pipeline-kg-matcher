# 0811 图谱修改建议

数据导入很干净（外键零悬空、计数与你们自带实例一致），下面 6 条是词表层面的问题，
不影响导入，但会影响工具能不能匹配到数据。行号相对 `0811/` 目录。

---

## 1. fastqc（T002）输入输出标错

`semantic_output` 写成了 `RAW_SINGLE_END_FASTQ`，但 fastqc 产出的是质控报告
（物理格式列已经写了 `HTML, ZIP`）。`semantic_input` 也是单端，而库里 0 个单端文件，
全是成对的 R1/R2。

**改**

| 文件 | 位置 | 改成 |
|---|---|---|
| `entities/tool.csv` | T002 `semantic_input` | `RAW_PAIRED_END_R1_FASTQ; RAW_PAIRED_END_R2_FASTQ` |
| `entities/tool.csv` | T002 `semantic_output` | `QC_STATS_REPORT` |
| `relations/tool_has_semantic_input.csv` | 第 4 行 | 拆成 `T002,RAW_PAIRED_END_R1_FASTQ` 和 `T002,RAW_PAIRED_END_R2_FASTQ` |
| `relations/tool_has_semantic_output.csv` | 第 5 行 | `T002,QC_STATS_REPORT` |

**不改**：fastqc 匹配不到任何数据，用它做质控的需求排不出流程；
`fastp -> fastqc` 这条 data 边两端没有交集（你们 10 条 data 边里唯一一条）。

## 2. `METADATA_SAMPLEINFO` 和 `METADATA_SAMPLE_INFO` 拼写分裂

工具只用前者（13 次），数据只用后者（20 个文件），交集为零。

**改**：统一到 `METADATA_SAMPLE_INFO`。`reference/formats.csv` 删掉
`METADATA_SAMPLEINFO` 那行；`relations/tool_has_semantic_input.csv` 的 13 行和
`entities/tool.csv` 对应工具的 `semantic_input` 改过来。

涉及 T044、T047、T048、T049、T050、T054、T055、T060、T061、T062、T063、T065、T066。

**不改**：这 13 个工具（生存分析、富集、WGCNA、单细胞通讯、UMAP 等）全都匹配不到
样本元数据文件，数据可用性判定一律显示缺输入。

## 3. BAI 没有工具消费或产出

库里 6,177 个 `DNA_ALIGNMENT_INDEX_BAI`，工具输入输出都是 0。
对比 VCF 索引 `DNA_VARIANT_INDEX_TBI` 有 1 个输入、3 个输出，应该是漏了。

**改**

| 文件 | 加一行 |
|---|---|
| `relations/tool_has_semantic_output.csv` | `T007,DNA_ALIGNMENT_INDEX_BAI`（samtools 建索引） |
| `relations/tool_has_semantic_input.csv` | `T008,DNA_ALIGNMENT_INDEX_BAI`（GATK 需要 BAM 索引） |

`entities/tool.csv` 对应列同步。GATK 若也产出 BAI，输出一并补。

**不改**：6,177 个 BAI 在图里是孤立的，说不清谁产生、谁使用。

## 4. 语义格式缺父子关系

**这条不是你们标错了。** 6,177 个 BAM 文件名全是 `HRR*.BQSR.bam`，标
`DNA_ALIGNMENT_BQSR_BAM` 比标通用 BAM 更准确。问题是工具侧写的是
`DNA_GENOMIC_ALIGNMENT_BAM`，词表里两者平级，匹配不上。

**改**：加一张 `reference/format_subclass.csv`：

```csv
child,parent
DNA_ALIGNMENT_BQSR_BAM,DNA_GENOMIC_ALIGNMENT_BAM
DNA_SOMATIC_SV_VCF,DNA_VARIANT_VCF_GENERAL
SCRNA_MATRIX_H5_ZIP,SCRNA_MATRIX_H5
```

导入成 `(:format)-[:subclass_of]->(:format)`，匹配时沿边向上找父类。

这三行是我们有把握的。下面几个也是"数据有、工具不认"，要不要挂父类你们判断：
`DNA_VARIANT_STATS_REPORT`、`RNA_SPLICEJUNCTION_TAB`、`SCRNA_MATRIX_H5`、
`SOMATIC_CNV_TSV`、`BIO_DATA_CONTAINER_OBJECT`、`OTHER_UNCLASSIFIED_DATA`。

**不改**：库里 16,457 个文件（占 `in_format` 的 26%）的语义格式没有任何工具认，
从已有 BAM 出发的需求都会判成无数据可用。

## 5. 删掉 `MUTATION_ANNOTATION_FORMA_MAF`

`reference/formats.csv` 第 13 行，少一个 T，零引用。正确的
`MUTATION_ANNOTATION_FORMAT_MAF` 在第 26 行，描述里也写了"tool 表 FORMA 拼写已归一"，
应该是修完忘删。

**改**：删掉第 13 行。

**不改**：不影响功能，就是多一个孤立节点，核对时容易误认为漏标。

## 6. `fastp -> bwa` 的 kind

`relations/tool_relationship.csv` 第 4 行标 `order`，但 fastp 输出 R1/R2、bwa 输入
R1/R2，有数据传递。同样吃 R1/R2 的 `fastp -> star`（第 3 行）标的是 `data`。

**改**：第 4 行 `order` 改 `data`。若确有业务理由认为只是执行顺序，请告知，我们按你们的来。

**不改**：`order` 表示无数据流，规划器不会把 fastp 的输出接到 bwa，WES 比对链会断。
我们目前在自己这侧按 `data` 处理。
