## 四、8 个疑点的定位结论

### ❌ Q2 `METADATA_SAMPLEINFO` / `METADATA_SAMPLE_INFO` —— 确认是错，建议合并

| 拼写 | 工具输入 | 工具输出 | T1 数据 | T2 数据 |
|---|---:|---:|---:|---:|
| `METADATA_SAMPLEINFO` | **13** | 0 | 0 | 0 |
| `METADATA_SAMPLE_INFO` | 0 | 0 | **18** | **2** |

两个拼写的使用是**完全互斥**的：工具侧只用前者，数据侧只用后者，交集为零。
两条描述说的是同一件事（样本元数据表）。这意味着任何声明需要样本元数据的工具，
**永远匹配不到实际的元数据文件**。

> 建议：`formats.csv` 只保留 `METADATA_SAMPLE_INFO`（数据侧已在用），
> `tool_has_semantic_input.csv` 的 13 行改成同一拼写。

### ❌ Q3 `MUTATION_ANNOTATION_FORMA_MAF` —— 确认是死节点，可安全删除

| 拼写 | 工具输入 | 工具输出 | T1 | T2 |
|---|---:|---:|---:|---:|
| `MUTATION_ANNOTATION_FORMA_MAF` | 0 | 0 | 0 | 0 |
| `MUTATION_ANNOTATION_FORMAT_MAF` | 4 | 2 | 0 | 2,355 |

零引用。而且正确拼写那条的描述里她自己写了"tool 表 FORMA 拼写已归一"，
说明修过了但旧节点忘了删。删除无任何影响。

### ❌ Q4 fastqc 的输入输出 —— 确认是错，两处都不对

她的 T002 声明：

```
semantic_input  = RAW_SINGLE_END_FASTQ
semantic_output = RAW_SINGLE_END_FASTQ
```

两个问题：

1. **输出错了**。FastQC 产出的是质控报告，不是 FASTQ。同类工具 T001 fastp 和
   T004 trim_galore 的输出都含 `QC_STATS_REPORT`，唯独 fastqc 输出 FASTQ。
2. **输入匹配不到任何数据**。`RAW_SINGLE_END_FASTQ` 在 T1 和 T2 里的计数都是 **0**，
   实际数据全是成对的 `RAW_PAIRED_END_R1/R2_FASTQ`。

连带后果：`fastp→fastqc` 是她标的 data 边，但两端语义格式交集为空——她 10 条
data 边里唯一推不出绑定的一条；双端 FastQC 也无法表达。

> 建议：`semantic_input` 改为 `RAW_PAIRED_END_R1_FASTQ; RAW_PAIRED_END_R2_FASTQ`
> （如需保留单端支持则一并列出），`semantic_output` 改为 `QC_STATS_REPORT`。

### ⚠️ Q5 `fastp→bwa` 标成 order —— 判定为标注不一致

| | 语义格式 |
|---|---|
| fastp 输出 | `RAW_PAIRED_END_R1_FASTQ`、`RAW_PAIRED_END_R2_FASTQ`、`QC_STATS_REPORT` |
| bwa 输入 | `RAW_PAIRED_END_R1_FASTQ`、`RAW_PAIRED_END_R2_FASTQ`、`REFERENCE_GENOME_FASTA` |
| 交集 | R1 + R2，非空 |

她把同样吃 R1/R2 的 `fastp→star` 标成了 `data`，同一模式两种标注。
我方按 `data` 处理，否则 WES 链路的数据流会被切断。

### ⚠️ Q6 6,177 个 BAI 无人消费 —— 疑似漏标

| 索引类型 | 工具输入 | 工具输出 | 数据文件数 |
|---|---:|---:|---:|
| `DNA_VARIANT_INDEX_TBI` | 1 | 3 | 5,788 |
| `DNA_ALIGNMENT_INDEX_BAI` | **0** | **0** | **6,177** |

TBI 是有工具消费和产出的，说明索引类文件不是被系统性忽略的设计，
BAI 属于单独漏掉。BAM 索引在变异检测里是必需输入。

> 建议：samtools 补 `DNA_ALIGNMENT_INDEX_BAI` 输出，gatk 补该输入。

### ✅ Q1 BAM 语义格式对不上 —— 她没错，是模型缺父子关系

工具侧统一写 `DNA_GENOMIC_ALIGNMENT_BAM`，数据侧 6,177 个 BAM 全是
`DNA_ALIGNMENT_BQSR_BAM`。取证后确认**她的数据标注是对的**：

```
文件名样式统计: hrr#.bqsr.bam  6177/6177
含 bqsr 或 recal 的比例: 6177/6177
```

这些文件确实都经过 BQSR 处理，标成更具体的 `DNA_ALIGNMENT_BQSR_BAM` 比通用 BAM 更准确。
两条描述也是包含关系："经过 BQSR 处理后的 DNA 比对 BAM"显然是"标准 BAM"的子类。

问题在于她的语义格式词表是**扁平的**，没有 IS-A 关系，所以声明通用 BAM 的工具
匹配不到具体的 BQSR BAM。这不是标注错误，是模型缺一层表达。

> 建议：加一张语义格式父子表（如 `format_subclass.csv`：
> `DNA_ALIGNMENT_BQSR_BAM -> DNA_GENOMIC_ALIGNMENT_BAM`）。
> 对当前业务无影响——我方按物理格式 `bam` 加 artifact 角色匹配，不走语义格式。

### ✅ Q7 T1 只有 4 种语义格式 —— 设计如此，不是错

```
T1: RAW_PAIRED_END_R1_FASTQ 13027 / RAW_PAIRED_END_R2_FASTQ 13026
    CLINICAL_DATA_EXCEL 18 / METADATA_SAMPLE_INFO 18
T2: VCF 8306 / BQSR BAM 6177 / BAI 6177 / TBI 5788 / 转录组 BAM 3288 / MAF 2355 ...
```

T1 = 一级原始数据（下机 FASTQ + 随附的临床和元数据表），
T2 = 二级分析结果（比对、变异、注释产物）。分工清晰且正确。
拿 BAM 当链路输入从 T2 取是符合业务语义的。

### 📦 Q8 `fastp` 和 `gatk` 没有知识卡 —— 执行端交付缺口，与图无关
