## 2. 我方的东西放在哪里

槽位名、WDL 绑定（`RNASeqPipeline.gtf_file` 这类）、输入变体、GATK tumor/normal 四槽——
这些是**执行端合同，不是知识图谱事实**，她的图里没有也不应该有。它们留在
`data/csv/catalog/`，由 `tool_catalog_source.py` 在运行时与她的图合并：

| 内容 | 来源 |
|---|---|
| 有哪些工具（51）、`has_function`、`suitable_for`、语义级 IO | 她的图 |
| NEXT 拓扑 | 她的 `next_tool` |
| 槽位名、`builder_param`、`wdl_target`、变体、GATK 四槽 | `data/csv/catalog/` |
| NEXT 数据边的 output/input 绑定 | `data/csv/relations/tool_relationship.csv` |
| `rnaseq_singletask` 的锁定步骤 | `data/csv/catalog/relationships.csv` 的 HAS_STEP |

两边不一致的地方不会被静默处理，而是进 `tool_catalog()` 返回值的 `divergence` 字段。
当前实测 `divergence` 全空：50 个运行时工具、12 对 NEXT，与她的图零分歧。

`tool_catalog()` 的输出契约一个字段没改，所以 `workflow_composer.py` 不受影响。

## 4. 按我方来的偏离项（共 5 处）

### 4.1 `fastp→bwa` 保留为 data 边，她标的是 order

她自己的数据证明这是数据边：fastp 输出 `RAW_PAIRED_END_R1/R2_FASTQ`，bwa 输入同样两个
格式，交集非空；而且她把同样吃 R1/R2 的 `fastp→star` 标成了 `data`。改成 order 会切断
WES 链路的数据流。**判定为她的标注不一致，保留我方的 data。**

### 4.2 multiqc 排除在原子层之外

她的图里 multiqc（T013）有 12 条入边。但 multiqc 是终端 QC 汇总器，没有下游消费它的
输出，把它放进原子链只会产生过不了闭集校验的 fan-in。按要求彻底移出：运行时目录排除
multiqc（50 个工具而不是 51），提示词里删掉教模型怎么写 MultiQC 步骤的段落，边界条目
改成"点名 MultiQC 也只是略去这步、其余照常生成，不得因此清空 candidates"，
`_deterministic_rnaseq_candidate_steps()` 里硬编码的 multiqc 步骤删除。

顺带发现那条确定性回退链因为含 multiqc 永远通不过 NEXT 校验，一直是死代码。

### 4.3 样本级 `specimen_types` 走旁路，不写进她的图

0811 的 `sample` 表改成 run 级后不再携带 `specimen_types`，而
`pipeline_router.STUDY_ROLE_RULES` 判定 tumor/normal 完全依赖它。

处理：`scripts/python/build_sample_specimen_backfill.py` 从改造前的逻辑备份提取 8,353 行到
`data/0811_supplement/sample_specimen_backfill.csv`，由 `Neo4jKGDataMatcher._apply_specimen_sidecar()`
在启动时加载成内存映射。**图里一个属性都不写**，且图上已有的值永远优先。
六个配对判据 study 覆盖率：HRA000021、HRA000873、HRA001272、HRA001748、HRA001749 均 100%，
HRA006499 为 482/523。

### 4.4 `read_pair` 从语义格式推导

0811 的 T1 没有 `read_pair` 列。原文件名启发式 `(_r?1|_f1|read1)` 要求下划线分隔，
漏掉 `10125714.R1.fastq.gz` 这类点分隔命名，26,053 个 FASTQ 里判不出 1,116 个。

处理：优先用她的 `semantic_format`（`RAW_PAIRED_END_R1_FASTQ` / `_R2_`），覆盖率 100%；
同时把 mate 正则扩成 `(_r?1|[.-]r1|_f1|read1)`，保留 `r` 为必需以免把单端名字里的
`.1`/`-1` 误判。修复后 FASTQ 缺 `read_pair` 数为 **0**。纯代码改动，不碰图。

### 4.5 `strategy` 归一到路由词表

0811 的 T1 保留原始策略 `WGS`/`bulk_RNA`/`WXS`/`WES`/`Targeted-Capture`/`TCR-Seq`/
`Unknow`/`sc-RNA`，而路由 profile 匹配的是 `WES`/`WGS`/`RNA-Seq`/`scRNA-seq`。

处理：按她自己的 `reference/strategy_modal_map.csv` 折叠（WXS→WES、Targeted-Capture→WES、
TCR-Seq→bulk_RNA），再映射到路由词表。归一后 WGS 9098、RNA-Seq 8485、WES 7570、
scRNA-seq 416、Clinical 18、Meta 18；484 行 `Unknow` 她自己标了 `action=skip`，
保留原值不猜测。纯代码改动，不碰图。

## 5. 她的图里发现的三处不一致

1. `formats.csv` 30 行里含两组近重复拼写：`MUTATION_ANNOTATION_FORMA_MAF` 与
   `..._FORMAT_MAF`、`METADATA_SAMPLEINFO` 与 `METADATA_SAMPLE_INFO`。
2. **工具 IO 和数据用了不同拼写**：`tool_has_semantic_input.csv` 写 `METADATA_SAMPLEINFO`，
   而 T1 数据标 `METADATA_SAMPLE_INFO`，两者指不到同一个 format 节点。
3. `fastp→fastqc` 是她标的 data 边，但她的 fastqc 只声明 `RAW_SINGLE_END_FASTQ`，
   与 fastp 输出的 R1/R2 没有交集——10 条数据边里唯一推不出绑定的一条。双端 FastQC
   在她的模型里也表达不了。

以上三条建议找师姐确认，本次未擅自修改她的数据。

30 条探针按六个维度设计，见 `scripts/probe_30_prompts.py`，明细在
`docs/probe_30_prompts_result.json`：能力问答 5、RNA-seq 上游 5、WES/WGS 5、
未原子化需求 6、输入方法冲突 4、数据可用性 5。除状态判定外还有一条横切不变量：
任何被接受的候选，`validation_ok` 必须为真且 `feasibility_status == ready`。

探针过程中定位并修掉的三个真问题：

1. **业务流程菜单漏掉了她新增的 27 个工具**。`_business_pipeline_menu_lines()` 只列
   96-case benchmark 里出现过的 pipeline，所以 `cnvkit_cnv_clinical` 这类新工具从来没被
   推给过 LLM，相关问题一律返回 unsupported。改成 benchmark 参考集与目录已注册 pipeline
   的并集。
2. **GATK→BCFtools 边界被过度应用**。"体细胞突变检测"的终点是 GATK 直接产出的 VCF，
   不需要 BCFtools 过滤，但模型把它读成命中边界而清空候选。边界措辞收紧为"仅当明确要求
   过滤/标准化/功能注释 VCF 时才命中"，并显式说明配对体细胞突变检测不属于该边界。
3. **执行端参考资源绑定缺失会否掉整条链**。`genome_annotation`、`interval_list` 属
   `reference_file`，本来就不需要用户数据，模型偶尔漏写 `asset_role` 就让整条链作废。
   改为确定性补全并记 warning。

## 8. 已知缺口

1. **配对 WES 稳定性约 5/6**。残余失败是单次 LLM 调用偶尔返回空，不是校验或数据问题。
   要做到确定性，可以照 RNA-seq 那条确定性回退链的模式补一条配对 WES 回退。
2. **按 study 反查"这批数据能做什么"未实现**。能力问答是目录级的，不接受 study 作用域。
3. 第 5 节那三处她的数据不一致。
4. `docs/mcp_delivery/` 下的交付快照仍是改造前的版本，未随本次更新重新打包。
