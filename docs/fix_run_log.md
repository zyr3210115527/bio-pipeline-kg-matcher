## Final engineering judgments

- **Largest effort overrun:** Stage C/D. Reconstructing the full canonical catalog and then publishing role/mate-aware paired topology atomically required more work than the isolated interface changes in A/B.
- **Shuffle finding:** Beyond positional binding, shuffle testing exposed that the original single-root connectivity rule could not represent a legitimate tumor/normal dual root. The replacement permits only two symmetric roots with exact tumor/normal roles and otherwise fails closed.
- **Previously unlisted unsafe D state:** Catalog replacement and NEXT publication were separate transactions. A crash between them could expose new slots with old edges or vice versa. They now commit in one transaction, and fault injection proved rollback.
- **CSV then sync trust:** It is now credible when using canonical CSV validation, explicit `--bootstrap-catalog`, exact fingerprint gates, idempotency, database-ID guards, and the atomic transaction. Plain `--apply` still intentionally does not bootstrap the catalog.
- **MultiQC behavior:** Stage two can now validly add MultiQC. One successful paired-WES run did so; therefore optional steps and `match_id` vary, while core bindings remained stable. Invalid extra chains were rejected.
- **Delivery pitfalls:** Exact Neo4j/Java versions, database-name matching during load, client timeout, clone database IDs, and eventual CSV fallback drift remain operational risks. The two package-layout script defects discovered by consumer acceptance are fixed.
- **Conservative choice to revisit:** Legacy generic fastp/BWA slots and the single GATK slot remain for compatibility. They should be deprecated only through a versioned tool-chain contract, not silently removed.
