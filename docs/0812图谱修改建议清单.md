## 1. `individual.csv` 那段整体错位一行还在（上一轮提过）

`sample_accession` 列里 449 个个体填的样本和 `sample.csv` 对不上，其中 347 个填的
恰好是下一行那个个体的样本。连带 115 个 sample 的 `study_accession` 与其 individual
对不上（`HRA001748` 111 个、`HRA007167` 4 个）。与 0811 逐字节相同，没有变化。

例：

```
individual.csv  HRI1703186 的 sample_accession = HRS2218012,HRS2218013
sample.csv      HRI1703186 的样本其实是        = HRS2218010,HRS2218011
                HRS2218012/13 实际属于 HRI1703187（下一行）
```

**改**：去生成脚本里找那处索引错位，大概率是循环下标偏了一位，或者两个 DataFrame
拼接时没有 `reset_index`。修一处，449 + 115 一起好。

**不改**：样本会挂到错误的病人和错误的队列上，按个体取样本、按队列统计都会错，
而且不会报错。

## 2. `tissue_type` 有三处填错

这版把 `tissue_type` 从 557 行补到 9,700 行，这是这次最大的改进。我们拿样本名里的
T/N 标记做了一次全量核对：3,048 个名字带明确标记的样本里，2,698 个和你们一致，
只有下面第一条矛盾。

### 2.1 HRA016026 整个 study 标成了 Normal

700 个样本全部 `tissue_type=Normal`，但其中 350 个样本名就叫 `L0240_Tumor`、
`L0542_Tumor`。另外 350 个叫 `_Normal`。

```
sample.csv   L0240_Tumor    tissue_type = Normal   ← 应为 Tumor
             L0240_Normal   tissue_type = Normal
```

**改**：这个 study 按样本名后缀重填，350 个 `_Tumor` 改成 `Tumor`。

**不改**：这个 study 完全失去配对能力——全是对照，没有肿瘤。我们这侧已按样本名兜底。

### 2.2 HRA000071 有 104 个血样标成了 Tumor

这个 study 是胶质瘤，572 个样本里 286 个 `T_` 开头的组织样本标 `Tumor` 没问题；
286 个 `B_` 开头、`specimen_type=Blood` 的样本里，182 个标 `Normal`、104 个标 `Tumor`。
同样的前缀、同样的 specimen，分成了两派。

```
sample.csv   B_CGGA_P100   specimen_type=Blood   tissue_type = Tumor    ← 应为 Normal
             B_CGGA_P101   specimen_type=Blood   tissue_type = Normal
```

**改**：这 104 行改成 `Normal`。

**不改**：血样会被当成肿瘤样本参与配对，体细胞变异检测会拿两份对照互相比。

### 2.3 HRA000001 的 557 行还是错位

`tissue_type` 填的是 `Blood`（材料），`specimen_type` 填的是 `Natural`。其余 study 的
`tissue_type` 都是 Tumor/Normal。这两列的值像是各错了一列。

**改**：`tissue_type` 应为该队列的角色（健康队列大概是 `Normal`），
`specimen_type` 应为 `Blood`。

**不改**：这 557 个样本判不出角色，不影响其他 study。

**不改**：这些样本判不出角色，相关 study 做不了配对分析。

## 4. 第二版的 `individual.csv` 少了 22 列，但你们图里还在

第二版（`neo4j-community-2026.08122.zip`）的 `individual.csv` 从 111 列变成 89 列，
少掉的全是 `adjuvant_treatment_*`：

```
adjuvant_treatment_type          2,108 个值
adjuvant_treatment_agents        1,076 个值
adjuvant_treatment_1..5_gap / _duration_d / _drugs / _type   合计约 500 个值
```

你们的实盘图里这些属性还在，计数和第一版 CSV 一模一样——应该是这次只增量插了 49 个
T2，没有按新 CSV 重建，所以图没受影响。但**CSV 和图已经对不上了**，谁按 CSV 重建谁就
丢这批数据。

**改**：看一下导出脚本的列选择，多半是筛列时漏了这一组。

**不改**：我们这侧先保留了第一版的 `individual.csv`，以便复现你们的图；但下次你们要是
按 CSV 重建，这 2,108 条辅助治疗记录就没了。

## 5. 新加的 49 个 T2 没有 `generated_from` 边

`HRA005191` 新增的 49 个分析结果（目录、jpeg、csv/tsv、rds）都挂上了 study、format、
level、modal 四类边，但 `T2_generated_from_T1.csv` 没有对应新增，这 49 个在图里追溯不到
上游 T1。其余 36,759 个 T2 有 64,545 条 `generated_from`。

**改**：如果这些结果确实是从该 study 的 T1 算出来的，补上对应边。

**不改**：这 49 个文件在图里是数据孤岛，"这个结果是从哪批原始数据来的"查不出来。
